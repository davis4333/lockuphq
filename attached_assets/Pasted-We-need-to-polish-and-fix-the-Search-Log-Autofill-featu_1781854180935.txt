Fix 4 — Correct the time-generation logic for upper/lower bunks

Current issue:
The app currently increments time by +1 minute for every row.

That is wrong when the same cell has upper and lower bunk entries.

Example of wrong behavior:
B1-106L = 6:44 P
B1-106U = 6:45 P

Correct behavior:
B1-106L and B1-106U are the same cell.
L means lower bunk.
U means upper bunk.

Both bunks in the same cell should receive the same time.

Correct example:
B1-106L = 6:44 P
B1-106U = 6:44 P
B1-107L = 6:45 P
B1-107U = 6:45 P
B1-108L = 6:46 P
B1-108U = 6:46 P

Required change:
Update the auto-time logic so time increments by unique cell number, not by row.

Create a normalized cell key for time assignment.

Normalization rule:

* If Area/Bunk ends in L, remove the final L for the timing key.
* If Area/Bunk ends in U, remove the final U for the timing key.
* Keep the original Area/Bunk value displayed and exported exactly as-is.
* Only use the normalized key internally for time grouping.

Examples:
B1-106L → timing key B1-106
B1-106U → timing key B1-106
B1-107L → timing key B1-107
B1-107U → timing key B1-107
B3-221L → timing key B3-221
B3-221U → timing key B3-221

Time assignment behavior:

* Start with the user-selected Start Time.
* Assign that time to the first unique normalized cell.
* Any rows with the same normalized cell key get the same time.
* When the normalized cell key changes, increase the time by 1 minute.
* Continue through the full roster this way.

Important:

* Do not combine L and U rows into one row.
* Keep both rows visible and exported.
* Only make them share the same time.

If a cell only has one bunk listed, it still gets its assigned time and the next unique cell gets +1 minute.

Review table behavior:

* Auto-filled times should follow this cell-based timing logic.
* The user must still be able to manually edit any time after auto-fill.
* If the user clicks Apply Start Time again, regenerate the time sequence using this corrected logic.

DOCX generation:

* Do not change the DOCX filling structure.
* Do not recreate the document.
* Do not change continuation-page logic.
* Only change the time assignment values before the rows are written into the original Search Log DOCX.

Acceptance criteria:

* B1-106L and B1-106U have the same time.
* B1-107L and B1-107U have the same time.
* Time only increases when moving to the next cell number.
* Original bunk labels with L and U remain visible in Area/Bunk Searched.
