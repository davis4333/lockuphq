We are adding a new feature to the existing Confinement Coach Lite app.

Feature name:
Search Log Autofill from Bed Book

Main goal:
Create a tool that lets the user upload a Bed Book roster file, review the parsed inmate/cell data, enter search-log details, and generate a completed Search Log DOCX by filling the exact original blank Search Log Word document provided with this prompt.

Critical requirement:
The app must fill the original Search Log DOCX form provided by the user.

DO NOT recreate the document.
DO NOT generate a lookalike form.
DO NOT make a new HTML table and export it.
DO NOT use HTML-to-DOCX for this feature.
DO NOT make a PDF-only version.
DO NOT stretch the existing table.
DO NOT add random rows that change the layout.

The completed download must be the original Search Log DOCX template with data inserted into the existing form cells.

Use the same original-document filling method already used in the existing Strip / Property Restriction paperwork feature. That feature already fills information into the original paperwork. Reuse that exact pattern as much as possible.

The user will provide this blank template:
Search log b-DORM BLANK.docx

Treat that file as the master Search Log template.

The blank Search Log page contains:

* DC6-2001 revision line
* Florida Department of Corrections title
* Search Log title
* Location field
* Search Log table
* Footer/instruction text

All of that must remain unchanged.

Only fill the blank data boxes/cells.

Privacy and session rules:

* Uploaded Bed Book files are used only for the current browser session.
* Do not save uploaded Bed Book data to a database.
* Do not save uploaded Bed Book data to localStorage.
* Do not send Bed Book data to AI.
* Do not send Bed Book data to any external API.
* Process the Bed Book locally in the browser if possible.
* Add a “Clear Uploaded Bed Book” button.
* Refreshing the page should clear the uploaded Bed Book roster unless the app already has an approved temporary session-only pattern.

Add a new dashboard card/tool:
Title:
Search Log Autofill

Subtitle:
Upload Bed Book and fill original Search Log

Feature workflow:

Step 1 — Upload Bed Book

Create an upload area where the user can drag and drop or manually select a Bed Book file.

Accept:

* .csv
* .xlsx
* .xls if practical

The Bed Book may be a CSV file that begins with:
SEP=|

If the first line starts with SEP=, use the character after SEP= as the delimiter.

Example:
SEP=|

Means the delimiter is:
|

The parser must handle this correctly.

Expected Bed Book columns:
Column A: BED-ID
Column B: DOCNUM
Column C: INMATE-NAME

The actual header row may not always be the first row. The parser should scan the file until it finds a row containing:

* BED-ID
* DOCNUM
* INMATE-NAME

Once found, use that row as the header row.

Step 2 — Parse and group roster

From the Bed Book:

BED-ID:

* Pull from Column A / BED-ID.
* This becomes the Search Log value for:
  Area/Bunk Searched
* Trim spaces.
* Preserve values exactly enough to maintain bunk/cell identity, such as B1-101L, B1-101U, B3-216L, etc.

DOCNUM:

* Pull from Column B / DOCNUM.
* This becomes part of the Search Log value for:
  Inmate Name/FDC Number
* The raw DOCNUM field may contain extra prefixes, underscores, spaces, or other characters.
* Extract the actual DC number using this logic:

  1. Prefer the rightmost pattern that matches one letter followed by five digits.
     Example: A12345
  2. Also allow six digits.
     Example: 123456
  3. If neither pattern is found, flag the row for user review instead of guessing.
* Do not invent DC numbers.
* Do not rewrite DC numbers.
* Do not use AI to guess DC numbers.

INMATE-NAME:

* Pull from Column C / INMATE-NAME.
* This becomes part of the Search Log value for:
  Inmate Name/FDC Number
* Trim extra spaces.
* Preserve the roster name format.
* Do not rewrite names with AI.
* Do not guess missing names.

Grouping rule:
The Search Log should create one entry per unique BED-ID / cell assignment.

If the Bed Book has two inmates assigned to the same BED-ID, only fill one Search Log row for that BED-ID.

In that one row:

* Area/Bunk Searched = the shared BED-ID
* Inmate Name/FDC Number = both inmates listed in the same cell

Format multiple inmates in the same Search Log cell using line breaks:

LAST, FIRST DCNUMBER
LAST, FIRST DCNUMBER

Do not use fake example names in the actual generated form.

Step 3 — Search Log setup fields

After the Bed Book is uploaded and parsed, show a setup form with these fields:

Location:

* Text field.
* Fill the Search Log Location box.
* Do not guess the location.
* Example user entry may be B-Dorm.

Date of Search:

* Date picker.
* Fill every Date cell in the Search Log with this same selected date.
* Format as MM/DD/YY to match the form style.

Start Time:

* Time picker.
* The app should auto-fill row times starting at the selected start time.
* Each next Search Log row should be 1 minute after the previous row.
* Example:
  Row 1: 4:45 P
  Row 2: 4:46 P
  Row 3: 4:47 P
* Times must remain editable before generating.
* Add a small warning:
  “Review and confirm all generated times before official use.”

Type of Search:

* Dropdown options:

  * Area
  * Pat
  * Strip
  * Other
* Default to Area.
* Fill every Type of Search cell with the selected value unless the user edits individual rows.
* Allow row-by-row editing in the review table.

Staff Name:

* Text field.
* Do not guess or auto-fill unless the user enters it.

Staff Rank:

* Dropdown options:

  * C/O
  * Sgt.
  * Lt.
  * Captain

Fill the Search Log column:
Name and Rank of Officer(s) Conducting Search

Format:
[RANK] [STAFF NAME]

Examples:
C/O Barrett
Sgt. Rivera
Lt. Johnson
Captain Smith

Do not invent staff names.

Discrepancies / Contraband Found:

* Text field.
* Default option should be None.
* Allow the user to bulk-fill all rows.
* Allow the user to edit each row individually before generating.
* Do not randomize this field.
* Do not invent contraband.
* Do not randomly place discrepancy items into the official form.
* This must reflect what the user manually enters and confirms.

Tablet Y/N:

* Dropdown:

  * Y
  * N
* Allow the user to bulk-fill all rows.
* Allow the user to edit each row individually before generating.
* Do not randomize this field.
* This must reflect what the user manually selects and confirms.

Step 4 — Review table before generation

After parsing the Bed Book and applying the setup fields, show a review table before generating the DOCX.

The review table should have one row per unique BED-ID / cell assignment.

Columns:

* Include checkbox
* Date
* Time
* Area/Bunk Searched
* Type of Search
* Inmate Name/FDC Number
* Name and Rank of Officer(s) Conducting Search
* Discrepancies/Contraband Found
* Tablet Y/N
* Validation Status

The user must be able to:

* Search/filter rows
* Exclude selected rows
* Edit any row manually
* Bulk apply Date
* Bulk apply Time sequence
* Bulk apply Type of Search
* Bulk apply Officer
* Bulk apply Discrepancies/Contraband Found
* Bulk apply Tablet Y/N
* Clear uploaded roster

Validation warnings:
Flag rows with:

* Missing BED-ID
* Missing inmate name
* Missing DC number
* Invalid DC number pattern
* Duplicate BED-ID grouping
* Missing date
* Missing time
* Missing type of search
* Missing officer
* Missing tablet value

Do not delete flagged rows automatically.
Let the user fix them, exclude them, or continue after confirming.

Step 5 — Fill the original Search Log DOCX

When the user clicks:
Generate & Download Search Log

The app must:

1. Load the exact original blank Search Log DOCX template.
2. Locate the existing Search Log table inside the Word document.
3. Fill the existing blank cells in that original table.
4. Preserve original formatting.
5. Preserve row height, borders, fonts, spacing, title, footer, and page layout.
6. Download a completed DOCX.

Columns to fill:

* Date
* Time
* Area/Bunk Searched
* Type of Search
* Inmate Name/FDC Number
* Name and Rank of Officer(s) Conducting Search
* Discrepancies/Contraband Found
* Tablet Y/N

Do not change:

* DC6-2001 revision text
* Florida Department of Corrections title
* Search Log title
* Table headers
* Footer/instruction text
* Existing form layout

Step 6 — Continuation pages

This is required.

The Search Log must document every unique bed/cell assignment from the uploaded Bed Book.

The app must use the original blank Search Log DOCX page as the master template page.

Process:

1. Parse the Bed Book.
2. Group inmates by BED-ID / cell assignment.
3. Create one Search Log entry per unique BED-ID / cell assignment.
4. Fill the first original Search Log page until all available blank data rows on that page are filled.
5. If there are more BED-ID/cell entries remaining, duplicate the entire original Search Log page exactly as it exists in the DOCX.
6. Insert a page break.
7. Fill the next duplicated Search Log page with the next group of entries.
8. Repeat this process until every unique BED-ID/cell assignment from the Bed Book has been documented.

Critical continuation rule:
Fill original page.
Then add another exact copy of that page.
Then fill that page.
Then add another exact copy.
Continue until complete.

Do not stretch the table.
Do not add extra rows to the bottom if it changes the layout.
Do not recreate the Search Log as a new table.
Do not generate a simplified continuation sheet.

Each duplicated page must preserve:

* Florida Department of Corrections title
* DC6-2001 revision line
* Search Log title
* Location field
* Table headers
* Existing row height/spacing
* Borders
* Font formatting
* Footer/instruction text
* Overall page layout

The only thing that changes on each page is the filled-in row data.

The Location field, Date fields, Type of Search fields, Officer field, Discrepancies/Contraband field, and Tablet Y/N field should continue filling across every duplicated page.

Example:
If the original Search Log page has 19 usable blank data rows and the Bed Book has 50 unique bed/cell assignments, generate:

* Page 1: entries 1–19
* Page 2: entries 20–38
* Page 3: entries 39–50

The final downloaded DOCX must be one Word document containing all completed Search Log pages.

If the code cannot safely duplicate the original DOCX page while preserving formatting, stop and show an error.
Do not generate a fake replacement form.
