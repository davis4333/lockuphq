Update the Search Log Autofill feature UI behavior so the Bed Book workflow and Manual Entry workflow behave like two separate collapsible modes.

Current issue:
The page currently shows Search Log Setup at the top all the time, then shows the selected entry method below. This makes the page feel cluttered and confusing.

Required behavior:
The user should choose one of these two modes:

1. Fill Search Log from Bed Book
2. Manually Fill Search Log

Only the selected mode should be expanded.
The non-selected mode should be minimized/collapsed.

Rename the entry method options to be clearer:

Option 1:
Fill Search Log from Bed Book

Option 2:
Manually Fill Search Log

Mode behavior:

When “Fill Search Log from Bed Book” is selected:

* Expand the Bed Book workflow.
* Show the Search Log Setup options needed for the Bed Book workflow.
* Show the Bed Book upload section.
* Show the bunk handling option.
* Hide/minimize the Manual Search Entry fields.
* Manual entry fields should not take up page space.

When “Manually Fill Search Log” is selected:

* Expand the Manual Entry workflow.
* Hide/minimize the Bed Book Upload section.
* Hide/minimize Bed Book-specific options, including bunk handling.
* Move/show the manual Search Log input fields under the Manually Fill Search Log section.
* The Search Log Setup card at the top should minimize/collapse so the manual workflow becomes the main visible workflow.
* Manual fields should only appear when Manually Fill Search Log is selected.

Important UI goal:
Do not show both full workflows at the same time.
The selected workflow should feel focused and clean.

Recommended layout:

Section 1:
Search Log Entry Method

Two large buttons/tabs:

* Fill Search Log from Bed Book
* Manually Fill Search Log

If Bed Book mode is selected, show:

* Bed Book Search Log Setup
* Upload Bed Book
* Bunk Handling
* Review Rows
* Generate & Download

If Manual mode is selected, show:

* Manual Search Log Setup / Manual Search Entry
* Add Search button
* Review Rows
* Generate & Download

Manual Entry workflow details:

When “Manually Fill Search Log” is selected, show a manual input form with these fields:

Persistent fields:

* Location
* Date

These should stay filled after adding a search row because they usually stay the same for the same log.

Row-specific fields:

* Time
* Area/Bunk Searched
* Type of Search
* Inmate Name/FDC Number
* Staff Name
* Staff Rank
* Discrepancies/Contraband Found
* Tablet Y/N

These should reset after the user clicks Add Search because they may change for each new search.

Manual input fields:

Location:

* Text input.
* Does not reset after Add Search.
* Example: B-Dorm, E-Dorm.

Date:

* Date picker.
* Does not reset after Add Search.

Time:

* Time picker.
* Resets after Add Search.
* Optional improvement: after Add Search, auto-increment the next time by 1 minute from the previous entered time, but still allow the user to manually edit it.

Area/Bunk Searched:

* Text input.
* Resets after Add Search.
* Examples: B1-106L, B1-106U, B1-106, Shower, Dayroom, Sallyport.

Type of Search:

* Dropdown.
* Options:

  * Area
  * Pat
  * Strip
  * Other
* Resets to the default selected type after Add Search, or stays on the last selected type if that is easier for workflow. Prefer keeping the last selected type because officers may enter several Area searches in a row.

Inmate Name/FDC Number:

* Text input or textarea.
* Resets after Add Search.
* User types the inmate name and FDC/DC number manually.
* Do not guess names.
* Do not guess DC numbers.
* Do not rewrite user-entered text.

Staff Name:

* Text input.
* Resets after Add Search unless a “Keep officer for next search” option is added.
* Since different officers may conduct different searches, default behavior should reset.

Staff Rank:

* Dropdown.
* Options:

  * C/O
  * Sgt.
  * Lt.
  * Captain
* Resets after Add Search unless a “Keep officer for next search” option is added.

Discrepancies/Contraband Found:

* Text input.
* Resets after Add Search.
* Example: None, Trash, etc.

Tablet Y/N:

* Dropdown.
* Options only:

  * Y
  * N
* Resets after Add Search.

Add Search button behavior:
When the user clicks “Add Search”:

1. Validate the current manual entry fields.
2. Add the manual search entry to the Review Rows table below.
3. Keep Location filled.
4. Keep Date filled.
5. Clear/reset the row-specific fields:

   * Time
   * Area/Bunk Searched
   * Inmate Name/FDC Number
   * Staff Name
   * Staff Rank
   * Discrepancies/Contraband Found
   * Tablet Y/N
6. Keep or reset Type of Search based on what feels best, but prefer keeping the last selected Type of Search so multiple Area searches can be entered quickly.
7. Focus the cursor back into the first row-specific field that should be filled next, preferably Time or Area/Bunk Searched.

Manual row output:
Each time Add Search is clicked, populate the Review Rows table with:

* Date
* Time
* Area/Bunk Searched
* Type of Search
* Inmate Name/FDC Number
* Name and Rank of Officer(s) Conducting Search
* Discrepancies/Contraband Found
* Tablet Y/N

Officer formatting:
Combine Staff Rank and Staff Name into the officer column.

Format:
[RANK] [STAFF NAME]

Example:
C/O Davis

Manual review behavior:

* The added manual rows should appear in the same Review Rows table used by the Bed Book workflow.
* The user should be able to edit any added row.
* The user should be able to exclude/remove any added row.
* The Generate & Download button should generate the original Search Log DOCX using these manually added rows.

Manual mode controls:
Add these buttons:

* Add Search
* Clear Current Entry
* Clear Manual Rows

Clear Current Entry:

* Clears only the current manual input fields.
* Does not clear Location or Date unless the user manually clears them.
* Does not remove rows already added to the Review Rows table.

Clear Manual Rows:

* Removes all manually added rows from the Review Rows table after confirmation.

Bed Book mode behavior:
When “Fill Search Log from Bed Book” is selected:

* Show the Bed Book setup fields and upload section.
* Bed Book mode should still support:

  * Group lower/upper bunks together by cell
  * List lower/upper bunks separately
* Bed Book rows should still generate into the Review Rows table.
* Bed Book generation should still fill the exact original Search Log DOCX.

Collapsed/minimized behavior:
When a mode is not selected:

* Do not show that mode’s full form.
* At most, show a small collapsed header/card.
* The page should not feel like it has unused forms sitting everywhere.

Professional UI requirements:

* The selected mode should be visually obvious.
* The selected mode should be expanded and easy to work in.
* The non-selected mode should be minimized.
* Keep the dark blue professional theme.
* Keep spacing clean and uniform.
* Do not make the page feel crowded.
* Manual entry fields should align cleanly in a grid.
* Add Search button should be prominent.
* Review Rows should stay below the active workflow.
* Generate & Download should stay below the Review Rows section.

DOCX generation:
Do not change the DOCX generation system except to support manual rows.

The generated file must still:

* Fill the exact original Search Log DOCX.
* Preserve the official form layout.
* Preserve continuation pages.
* Preserve the DC6-2001 revision/form number on every generated page.
* Use the same original document filling method.
* Not recreate the form.

Validation:
For manual Add Search, warn if required fields are missing:

* Location
* Date
* Time
* Area/Bunk Searched
* Type of Search
* Inmate Name/FDC Number
* Staff Name
* Staff Rank
* Tablet Y/N

Do not silently add incomplete rows unless the user confirms.

Acceptance criteria:

* User can choose Fill Search Log from Bed Book or Manually Fill Search Log.
* Only the selected workflow is expanded.
* Bed Book workflow shows Bed Book setup/upload options.
* Manual workflow hides Bed Book options and shows manual search input fields.
* Manual search input fields are hidden unless Manually Fill Search Log is selected.
* In Manual mode, clicking Add Search adds the filled entry into the Review Rows table.
* After Add Search, Location and Date stay filled.
* After Add Search, Time, Area/Bunk, Inmate Name/FDC Number, Staff Name, Staff Rank, Discrepancies/Contraband, and Tablet Y/N reset for the next search.
* Manual rows remain editable in the Review Rows table.
* Generate & Download works for manually entered rows.
* Generate & Download works for Bed Book rows.
* Final output still fills the exact original Search Log DOCX form.
* The page looks cleaner, more professional, and less cluttered.
