## Architecture decisions

- Search Log timing is per *physical cell*, not per row: `normalizeTimingCellKey` strips a trailing `L`/`U` so a cell's upper & lower bunks share one search time. `resequenceTimes` advances +1 min per unique *included* cell and leaves excluded rows untouched.
- The officer column is a multi-staff list (`SetupFields.staff: StaffMember[]`) combined as `"RANK NAME, RANK NAME"` via `combineStaff`. "Apply Officer" rewrites *included* rows only.
- Bed Book delimiter detection is internal and header-aware (no UI control): a leading `SEP=` wins, otherwise comma/pipe/tab/semicolon are scored by which best reveals the BED-ID/DOCNUM/INMATE-NAME header row (tie-break by column count).
- `PageShell` honors its `maxWidthClass` prop; the Search Log review uses `max-w-7xl` with a `table-fixed` + `colgroup` layout (sticky `thead`, vertical scroll) so the table never causes horizontal page scroll.
- Search Log has two **entry methods** (`EntryMethod`: `bedbook` | `manual`) and, for Bed Book, two **bunk-handling** modes (`BunkHandling`: `byCell` | `byBunk`). The page stores `parsed` + `bedBookRows` + `manualRows` separately and derives the active set, so switching entry method *hides* (never destroys) the other set and switching bunk handling re-groups losslessly from the retained `parsed`. `ReviewRow.source` drives source-aware validation; every row (both sources) is additionally checked for one-line overflow per column (see below). Manual rows otherwise only warn on blank fields (area may be a free location, inmate text is never rewritten); Bed Book rows also require BED-ID/DC numbers.
- **Global one-line fitting (all columns).** The filler keeps EVERY filled data cell on one physical line by shrinking **only** that cell's own inserted-run font down a single ladder (`ONE_LINE_CANDIDATES`, 10pt → 6pt floor); it reads each cell's real `w:tcW` (fallback `SEARCH_LOG_COL_TWIPS[idx]`). If a value still won't fit at 6pt it is **not** truncated — instead `searchLogCellFitsAtMin` raises a non-blocking per-field review warning ("This <Field> field may be too long to fit on one line at 6 pt. Review before generating") so the user shortens it. The UI and filler share the exact same width math in `searchLogTextFit.ts` (nbsp==space and the non-breaking hyphen==hyphen in the metrics, so raw-text and substituted-text measurements match). `ReviewRow.inmateFit` is now **vestigial** (a no-op kept only so callers compile) — grouping still controls whether the review table joins inmates with `" / "` vs newlines, but every column is one-lined and font-fit regardless.

## Product

The **DR Writer — Charge 6-1** module drafts a disciplinary-report narrative for disobeying a verbal/written order (FDC Charge 6-1). The officer enters firsthand facts, runs **Check Facts** (server-side `evaluate6_1` returns RED blockers / YELLOW review notes / GREEN), then **Generate Narrative**, which calls Anthropic's Claude **server-side** (never from the browser) to format the narrative from the officer's facts. A privacy notice (exact approved wording) sits directly above Generate; Generate is gated behind running Check Facts first, and any field edit forces a re-check. Only Charge 6-1 is selectable. All facts are sent to the server only to reach Claude — nothing is stored or logged (the route logs only an error's class name, never intake or narrative content). The key requirement is `ANTHROPIC_API_KEY` in Replit Secrets.

Confinement Desk Coach (cdc-coach) is a training/desk-aid command center for confinement officers. The **Lock-Up Slip** module generates a confinement placement narrative and also offers a **Lock-Up Packet** section that bundles, for the SINGLE inmate already entered in the slip, the narrative (as a `.txt`) plus checkbox-selected filled forms — DC6-229 Daily Record, DC6-221 Cell Inspection, and Confinement Rules (all checked by default) — into ONE downloadable `.zip`. It adds an Officer Name field and an Officer Rank dropdown (C/O, Sgt., Lt., Captain), a free-text **DC6-229 Status** field (shown when DC6-229 is selected; fills ONLY the DC6-229 Status blank with whatever the officer types — e.g. A5/A6/CM1/C1 — and is kept fully separate from the slip's AC/DC confinement category), plus a review-confirm checkbox that gates the "Generate & Download Full Lock-Up Packet" button. The DC6-229's 7 daily dates auto-derive from today (back to the most recent Sunday, or the prior Sun–Sat week ending Saturday when today is Sunday — see `autoDc6229WeekStartIso` in `LockUpSlip.tsx`). Other modules include Strip/Property Restriction, and **Search Log** — either upload a Bed Book roster (CSV with optional `SEP=|`, or XLSX/XLS) or build entries by hand (Manual Entry), then review/edit the rows and generate a completed Search Log by filling the original government Word form (continuation pages added automatically per 19 entries). For Bed Book uploads, bunks can be grouped by physical cell (both inmates in one shrunk-to-fit box) or listed separately. A second module, **DC6-229 Daily Record**, also takes a Bed Book upload or Manual Entry and generates ONE downloadable DOCX packet containing a complete 2-page DC6-229 (Daily Record of Special Housing) per inmate — page 1 filled (Inmate Name, FDC#, Cell# after the form's printed "B", Status) plus the 7 Sun–Sat dates of a chosen Sunday week-start dropped into the daily grid, page 2 left untouched, each form on a new page. All roster and manually entered data is processed in-browser only — never saved, stored, or transmitted.

## Gotchas

- Two different "cell" counts exist and must stay labeled distinctly: **Entries** = review rows (grouping depends on bunk handling) vs **Unique cells** = physical cells after L/U merge (`normalizeCellKey`). They differ (e.g. 6 bunks → 3 cells); never label both "cells" or the UI looks self-contradictory.
- Never recreate or modify the DOCX filler (`searchLogDocxFiller.ts`), the `public/*-template.docx` government forms, the continuation-page logic, the footer mirroring, or the section/bookmark logic — only the data boxes get filled, and the **only** per-cell change allowed is the inserted run's font size (never column widths, row heights, or page size). Every cell is now globally one-lined and font-fit (10pt → 6pt floor); `ReviewRow.inmateFit` is vestigial — do **not** reintroduce an `inmateFit === false` multiline branch.
- **DC6-229 Status is its own free-text field, NEVER derived from AC/DC.** In the Lock-Up Slip packet, the DC6-229's Status (F21) is fed by a dedicated `dc6229Status` free-text input (`LockUpSlip.tsx`), passed through as `generateLockUpPacket({confinementStatus: dc6229Status.trim()})`. The slip's AC/DC `fields.confinementType` (Administrative/Disciplinary Confinement) drives ONLY the narrative and the slip's confinement-category select — it must never populate the DC6-229 Status. Do NOT reintroduce the old `confinementStatusCode(fields.confinementType)` coupling. A blank DC6-229 Status is a NON-blocking amber warning ("DC6-229 Status is blank. This is separate from AC/DC confinement category."), gated only by the existing review-confirm checkbox — never a hard block, never silently filled with AC/DC. Trim-only on the typed value (no dropdown, no auto-convert).
- The DC6-229 filler (`dc6229DocxFiller.ts`) is similarly sacrosanct: it clones the real template's first section per inmate by an absolute-index FORMTEXT fill (F1 name, F10 FDC#, F19 cell, F21 status; F18 is the PRINTED "B" anchor and must never be written) and injects the 7 dates into the 2nd top-level table's alternating `vMerge=restart` cells. For each target date box it **replaces** the cell's single empty paragraph with one fully-controlled centered, single-spaced paragraph (preserving `tcPr`: width/borders/`vMerge`/`vAlign`) — it does NOT append a run to the template's paragraph, because the template's date boxes are inconsistently styled (the first data box is `Heading3`/left, the other 13 are plain/centered) and appending let Word word-wrap differently per cell. The "Day + Date" date format is carried as `"Sun\n06/14/26"` (newline) and `buildResultRuns` turns the `\n` into a hard `<w:br/>` so the day always stacks directly over the date. It validates the field count (39), the "B" anchor position, the date-box count (14), 7 dates per form, and that each target box actually has a paragraph to replace, failing loudly on any drift. Do not recreate the DC6-229 form, change which fields are filled, or fill the remarks fields (F25–F38). The DC6-229 Bed Book parser intentionally **requires** a header row (BED-ID/DOCNUM/INMATE-NAME) just like Search Log — do not add a blind headerless positional fallback (it would silently misread arbitrary spreadsheets).
- `normalizeCellKey` lives in `bedBookGrouper.ts` (not the row builder) to avoid a circular import; `normalizeTimingCellKey` is a back-compat alias re-exported from `searchLogRowBuilder.ts`.
- The Lock-Up Packet fillers (`dc6221CellInspectionFiller.ts`, `confinementRulesFiller.ts`) are equally sacrosanct: they fill ONLY the original `.docx` templates (never recreate / HTML-to-DOCX) and must **fail loudly** (throw `Dc6221DocxError` / `ConfinementRulesDocxError`) if any target cell/label/anchor cannot be located — never silently skip. DC6-221 fills **TABLE 0 only** (name r0c1, number r0c4, cell# appended after the printed "B" anchor in r2c0, date entered after the "Entered:" anchor in r2c1) and marks SAT (col 1) + N/A (col 2) on the **entered / top-left side only** for the 12 condition rows; the exited (right) columns and ALL signature cells are left blank. Confinement Rules fills name/FDC/date (r27) and officer name/rank/date (r29); signature cells (index 2) stay blank. `markWordInCell` **strikes through only** (`<w:strike/>`, NOT bold) an EXISTING template word (e.g. "SAT", "N/A") by reusing already-escaped `<w:t>` slices — it does NOT add new text, so a literal word's count in the XML is unchanged after marking. **Never re-add `<w:b/>` to the mark:** bold widens the glyphs, which pushes the tight condition cell ("GOOD/ SAT/ POOR", 7pt @ 1440 twips) to wrap an extra line, growing every shared row height and reflowing band-2 content onto page 2 — the exact bug users report. Strikethrough (like underline) adds zero width/height, so pagination stays byte-identical to the blank template. Do not fill remarks/signature lines on either form.
- **DC6-221 condition cell one-line shrink (user-authorized exception).** The user explicitly required the printed "GOOD/ SAT/ POOR" rating in the FILLED (top-left / entered) box to sit on ONE physical line with SAT struck. The template prints it at 7pt (sz 14) which wraps to two lines in the 1440-twip box. `markWordInCellFitOneLine` (in `docxCellUtils.ts`) is the ONLY place allowed to shrink *printed template text*: it re-emits every run in that one cell at a single fitted size (replacing existing `w:sz`/`w:szCs`, not duplicating; strike goes BEFORE `w:sz` per CT_RPr order) and strikes the target word. Scope is `cells[1]` only — the exited (col 3) and right-box condition cells are NEVER touched, so the shared row height (and 2-page pagination) is governed by those untouched cells; shrinking can only reduce height, never add a page. Verified empirically: 6.5pt still wraps, 6pt fits — the shared TNR metric runs ~15% optimistic vs LibreOffice for this tiny text, so the helper applies a `FIT_SAFETY` factor (1.15) before picking the largest fitting candidate (lands on 6pt). N/A is struck with plain `markWordInCell` (its cell already fits one line). Do NOT extend this shrink to any other printed text.
- **Lock-Up Packet one-line font-fit (DC6-221 + Confinement Rules).** Every inserted value is kept on ONE physical line by shrinking ONLY the inserted run's font (10pt → 6pt floor), never the template's printed labels, widths, heights, or page size. The fit math is shared with the Search Log via `searchLog/searchLogTextFit.ts` (`estimateTextTwips`, `usableCellTwips`, `ONE_LINE_CANDIDATES`); the helpers live in `lockUpPacket/docxCellUtils.ts`: `injectFittedRunIntoEmptyParagraph` (empty cells — sizes the value to the cell's real `w:tcW`) and `appendFittedRunAfterAnchor` (the DC6-221 cell#/date boxes — appends the value as its OWN run after the label run, sized so printed-label-width + value fits). Both pin the inserted run to Times New Roman so the rendered width matches the metrics (rFonts MUST come before `w:sz` inside `rPr`). The cell# value is now a separate run after the printed "B" (no longer concatenated into the label's `<w:t>`). Like the Search Log, values are never truncated — if a value won't fit even at 6pt it's emitted at the floor. To re-verify visually: a tsx harness in `artifacts/cdc-coach/` that stubs `globalThis.fetch` to `readFileSync` the template + writes the filled blob, run with `node ../../node_modules/.pnpm/tsx@*/node_modules/tsx/dist/cli.mjs <harness>.ts` (run from the artifact dir so the `@/*` tsconfig alias resolves), then `soffice --headless --convert-to pdf` + `pdftoppm -png`.
